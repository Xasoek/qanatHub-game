# One Sol to Rescue — руководство команды

**Проект для NASA Space Apps Challenge 2026 · 5 участников**

## 1. Цель проекта и стек

One Sol to Rescue («Один сол до помощи») — образовательная браузерная игра для детей 7–12 лет. Марк и робот Бип поддерживают работу марсианской базы «Заря» в течение 30 солов до прибытия помощи. Игрок следит за кислородом, едой и состоянием базы, распределяет энергию между шестью системами, реагирует на бури и солнечные вспышки, а в финале видит последствия своих решений.

| Направление | Технологии |
| --- | --- |
| Игра и интерфейс | HTML5, CSS3, Vanilla JavaScript (ES-модули) |
| Графика и звук | Встроенный SVG, анимации CSS и JS, Web Audio API |
| Научные данные | NASA DONKI REST API, Fetch API, встроенный архив |
| Сохранения и кэш | `localStorage` с обработкой недоступного хранилища |
| Разработка и проверка | Node.js 22, npm, esbuild, Git |
| Совместная работа и выпуск | GitHub, GitHub Actions, GitHub Pages |

Исходники собираются в один корневой `index.html`. Игрок открывает его в браузере, в том числе через `file://` без сети. CSS, JavaScript, SVG и архив NASA встраиваются в сборку. Сервер, регистрация и сетевые запросы для основной игры не требуются. Режим свежих данных включается по выбору игрока.

Стартовая сборка уже показывает экран базы, переключает EN/RU, позволяет выделить энергию очистителю и закончить сол. Полный набор событий, баланс, сохранения и данные NASA входят в задачи ниже. Порядок запуска описан в [README](README.md).

## 3. Роль 1 · Движок и баланс

- Держите числа в `CONFIG`. Миссия длится 30 солов, номинальная продолжительность сола на скорости ×1 составляет 120 секунд. Там же задавайте ресурсы, кубики, стоимость систем и ремонта, рост культур, вероятности событий, радиацию, уровни Cadet и Engineer, модификаторы Gale, Jezero и Arcadia.
- Развивайте общий `STATE` и публичный API. Движок применяет решения, расходует ресурсы и определяет исход партии. Реализуйте все шесть систем: очиститель воздуха (`air`), теплица (`farm`), ремонт (`repair`), обогрев (`heat`), связь (`comms`) и наука (`science`).
- Реализуйте семь событий: Dust Storm, Solar Flare, Air Purifier Failure, Dusty Panels, Earth Advice, Abandoned Rover Supplies и Cold Night. Движок запускает таймер выбора во время бури на 10 секунд в Engineer и 15 секунд в Cadet. UI показывает обратный отсчёт, движок применяет выбранное действие или вариант по умолчанию по истечении реального времени. Ускорение сола сохраняет длительность этого таймера.
- Сохраняйте отложенные последствия в `pending`, а решения и цену в `log`. Связывайте последствия с исходным решением. Примеры — трещина после длительного отсутствия ремонта, рост усталости без обогрева и падение выработки энергии из-за состояния панелей.
- Реализуйте сохранение, загрузку и итоговый отчёт о победе или аварийном сне. При недоступном хранилище партия продолжается, а API возвращает результат по контракту.
- Используйте числовой сид для воспроизводимых сценариев. В `tools/sim.js` сравните разумную и случайную стратегии на серии из 1 000 партий или больше. Цели баланса из ТЗ — 40–60% побед для разумной стратегии и менее 10% для случайной. Запишите сиды и результаты в PR.

- [ ] Последствия связаны с решениями. Сохранение и загрузка восстанавливают партию.

## 8. Работа с Git и GitHub

Установите Git и Node.js 22 с npm, примите приглашение и настройте SSH-доступ к GitHub. Затем клонируйте репозиторий и запустите проверки.

```bash
git clone git@github.com:Xasoek/qanatHub-game.git
cd qanatHub-game
npm ci
npm test
npm run build
npm run build:check
```

Для первой задачи возьмите существующую ветку роли. Пример для роли 2.

```bash
git fetch origin
git switch --track origin/role-2/ui
git merge origin/main
```

Если локальная ветка уже создана, переключитесь через `git switch role-2/ui`. Для следующей задачи создайте отдельную ветку от свежей `origin/main`, например `git switch -c role-2/intro origin/main` после `git fetch origin`. Разработку ведите в рабочих ветках и вносите изменения в `main` через PR.

Перед коммитом выполните проверки из блока выше. Откройте `index.html` без сети, начните день, выделите кубики очистителю и завершите сол. Проверьте переход к солу 2 и переключение EN/RU. Проверьте изменения перед добавлением в коммит. Пример ниже включает сгенерированный HTML, поскольку изменения интерфейса влияют на сборку.

```bash
git status
git diff
git add src/ui.js src/art.js src/style.css index.html
git diff --cached
git commit -m "feat(ui): add the Mars base interface"
git push -u origin HEAD
```

Выберите префикс коммита по смыслу: `feat` для новой функции, `fix` для исправления, `refactor` для переработки кода, `docs` для документации, `test` для проверок, `style` для оформления или `chore` для инструментов. Для следующих коммитов в той же ветке используйте `git push`.

1. В GitHub откройте **Pull requests → New pull request**. Выберите `main` как **base**, свою ветку как **compare**.
2. В заголовке назовите результат, например `feat(engine): implement oxygen and food systems`. В описании укажите роль, что изменилось, какие контракты затронуты, что проверили и что осталось. Привяжите Issue, если оно есть.
3. Отправьте PR на проверку роли 5 и владельцам затронутых модулей. Просмотрите вкладки **Files changed** и **Checks**. Исправления отправляйте в ту же ветку.
4. После объединения зависимых изменений обновите свою рабочую ветку командами `git fetch origin` и `git merge origin/main`. Согласуйте разрешение конфликтов с владельцами. При конфликте в `index.html` сначала уладьте изменения в исходниках, затем выполните `npm run build` и добавьте заново сгенерированный файл.

Дополнительные детали описаны в [CONTRIBUTING.md](CONTRIBUTING.md) и [инструкции GitHub по созданию PR](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request).

## 10. Контракты интеграции

Публичные сигнатуры и форматы описаны в [CONTRACTS.md](CONTRACTS.md). Импортируйте именованные экспорты с расширением `.js`. Проверяйте формы данных по контракту, в том числе в тестовых заглушках.

Пример `STATE` при старте партии с настройками по умолчанию.

```javascript
{
  sol: 1, phase: "morning", speed: 1, paused: false, status: "playing",
  site: "gale", difficulty: "engineer",
  oxygen: 15, food: 20, damage: 0, cubes: 6,
  alloc: { air: 0, farm: 0, repair: 0, heat: 0, comms: 0, science: 0 },
  panels: { total: 4, broken: 0, dusty: 0 },
  crop: { type: "radish", progress: 0 },
  dose: 0, fatigue: 0, crates: 0, stars: 0,
  weather: "clear", forecast: null, scrubberBroken: false,
  pending: [], log: [], solarMode: "archive", flares: [], seed: 0,
}
```

| Передача | Контракт |
| --- | --- |
| Движок → UI | UI читает актуальный `STATE`, который движок может заменить при старте или загрузке. Ключевые группы — ход и фаза, сложность и место, ресурсы, распределение кубиков, панели и урожай, погода, последствия, журнал и данные о вспышках. Движок владеет изменениями состояния. |
| UI → движок | `newGame({site, difficulty, seed, solarData})`, `allocate(system, delta)`, `endSol()`, `tick(dtMs)`, `resolveEvent(id, choice)`, `setSpeed(x)`, `skipToDecision()`, `save()`, `load()`, `getEndReport()`. `on(type, fn)` возвращает отписку. Тема `phase` передаёт `{sol, phase}`, `gameover` — отчёт `{status, sol, chains}`. Для `event` согласована форма `{id, type, choices, timeoutMs}`: отправляйте обратно те же ID события и варианта. |
| Данные NASA → UI и движок | `loadSolarData({mode})` возвращает `{mode, flares, asOf, noticeKey}` с фактическим режимом `archive` или `live`, датой или `null` и ключом уведомления или `null`. UI загружает данные и передаёт результат как `solarData` при старте. `SOURCES` содержит `{id, title, url}` для экрана источников. |
| Локализация → UI | `TEXT.en`, `TEXT.ru` и `t(lang, key, vars)`. Используйте общие вложенные ключи вроде `game.turn` и подстановки вроде `{sol}`. Вставляйте переводы через `textContent`. Согласуйте ключи для уведомлений NASA, событий и итогового журнала. |
| Графика → UI | `renderBase(state)` возвращает встроенный SVG. UI задаёт доступную подпись и вызывает отрисовку с актуальным состоянием. |
| UI → точка входа и сборка | `mountGame(root)` монтирует игру. `src/main.js` вызывает монтирование один раз. Сборщик встраивает JS, CSS и SVG в корневой HTML. |

Время в API передаётся в миллисекундах. Кислород и еда измеряются в солах, энергия — в кубиках, урон — в процентах. `cubes` означает свободные кубики, `alloc` — уже распределённые. Для изменения формата состояния или полезной нагрузки события приводите пример в PR и обновляйте потребителей вместе с контрактом.
